# 논술 마스터 호출·트래픽 운영 기준

## 실행 경계

문제 생성은 관리자 요청 뒤 독립 생성 엔진에서 구조화 결과와 QA 결과만 서버에 저장한다. 학습 화면은 저장된 `question_bank` 데이터만 조회하며, 문제를 보여 줄 때 AI를 호출하지 않는다. 문장 첨삭도 학습자가 명시적으로 요청할 때만 평가 엔진을 실행하고, 결과는 사용자·과정·문항·문장 지문 해시 기준으로 저장·재사용한다.

## 호출 최소화 원칙

| 영역 | 허용 호출 시점 | 절감 규칙 |
| --- | --- | --- |
| 문제 생성 | 관리자 생성 버튼 | QA 통과 결과만 초안·승인 저장, 화면 렌더링 중 생성 금지 |
| 문장 맞춤 피드백 | 학습자 `AI 피드백 받기` 버튼 | 동일 문장은 24시간 캐시 재사용, 진행 중 요청 병합 |
| 커리큘럼·이론 | 페이지 진입 후 1회 | 정적 레슨 구조를 유지하고 활성 콘텐츠만 병합 |
| DB 목록 | 변경 성공 뒤 해당 키만 갱신 | 전체 무효화·주기적 폴링 금지 |

## 문장 피드백 엔진 프롬프트 원칙

> 학생이 직접 작성한 한 문장을 분석한다. 원문 의도를 보존하고, 점수만 제시하지 말고 좋은 점 1~2개, 고칠 부분 1~2개, 구체적 수정 문장 1개를 제공한다. 과정 수준에 맞는 한국어를 사용한다. 교사 최종 첨삭이나 장기 학습 모델을 대체한다고 주장하지 않는다. 반드시 구조화 JSON만 반환한다.

## 검증 기준

서버는 문장 길이, 사용자 과정 권한, 문항 활성 상태를 먼저 확인한다. 결과 JSON은 점수 범위·배열 길이·개선 문장 존재를 검증한다. AI 호출 실패 시 문장 규칙 기반 안내만 반환하고 실패 결과를 캐시에 저장하지 않는다.
