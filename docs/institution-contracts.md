# 기관 계약·정산 제외 설계

학교·기관과 계약한 경우 교사의 첨삭을 개별 정산하지 않고, 계약으로 정한 횟수(토큰)로 관리하기 위한 구조입니다.
Codex가 구조를 설계·검증하고, 코드와 대조해 1단계 범위를 구현했습니다.

## 요구사항

1. 교사가 자기 반을 지도할 때 첨삭·지도 활동을 **개별 정산에서 제외**할 수 있다.
2. 학교·기관 계약은 **첨삭·AI 첨삭·관리**의 토큰 수를 관리자가 계약에 따라 정하고, 해당 반의 교사는 **건별 개별 정산을 하지 않는다**.
3. 기관 소속 회원은 **회원 단위로** 개별 정산이 되지 않도록 관리한다.

## 핵심 규칙

| 규칙 | 내용 |
|---|---|
| 토큰의 뜻 | LLM 토큰이나 금액이 아니라 **서비스 이용 횟수**. 첨삭 1건 / AI 첨삭 1회(성공한 것) / 관리 1건(출결 신규 기록·공지·과제 생성) |
| 활동 시점 고정 | 활동이 처음 완료된 시점의 정책을 `teacher_activity_accounting`에 스냅샷으로 기록. 계약·소속이 나중에 바뀌어도 과거 활동의 해석은 바뀌지 않음 |
| 자동 제외 우선순위 | ① 기관 계약이 연결된 반에서 한 활동 ② 기관 소속 학생에 대한 활동 ③ 기관 소속 교사의 활동 |
| 수동 제외 | 교사가 본인 활동을 사유와 함께 제외. 자동 제외는 바꿀 수 없고, 확정·지급된 달은 바꿀 수 없음. 되돌리기는 제외한 사람이나 관리자만 |
| 수정은 새 활동이 아님 | 같은 활동은 한 번만 기록(첨삭 수정, 과제 재채점, 워크북 첨삭 재저장은 새 건이 아님). 활동 시각은 처음 완료한 시각 |
| 예산 차감 | 조건부 갱신 한 번으로 한도 안일 때만 차감(마지막 1건에 동시 요청이 와도 한 건만 통과). 작업이 실패하면 되돌림 |
| 한도 소진·계약 만료 | 새 이용을 막고 "기관 담당자에게 문의"로 안내. **개인 이용권·체험으로 넘어가지 않음**. 연결된 반의 활동은 계속 개별 정산에서 제외 |
| 이용 자격 우선순위 | 학부모 거부 → 기관 계약 → 개인 이용권 → 7일 체험 → 이용권 필요 |
| 확정 | 정산 확정 직전에 현재 장부로 다시 계산. 확정된 정산서는 이후 단가·계약이 바뀌어도 변하지 않음 |
| 과거(장부 도입 전) 활동 | 장부에 없는 활동은 이전처럼 개별 정산 대상으로 계속 집계 |

## 데이터 (마이그레이션 0050, 새 테이블 5개 + 컬럼 1개)

- `institution_contracts`: 계약(기간·상태·3가지 예산 한도와 사용량)
- `institution_members`: 기관 소속 회원(회원 단위 정산 제외, 학생은 계약 연결 가능)
- `institution_usage`: 예산 사용 장부(같은 출처는 한 번만 차감)
- `teacher_activity_accounting`: 교사 활동별 정산 대상 여부(자동·수동 제외, 정책 스냅샷)
- `institution_audit_logs`: 계약·예산·반 연결·소속·정산 제외 변경 이력
- `learning_groups.contractId`: 반이 연결된 기관 계약

## 운영 순서

1. 마이그레이션 0049(결제·정산)와 0050을 적용합니다. 새 테이블·컬럼만 추가하며 기존 데이터는 바꾸지 않습니다.
   ```bash
   node scripts/apply-migration.mjs drizzle/0050_institution_contracts_and_settlement_accounting.sql          # 계획만 출력
   node scripts/apply-migration.mjs drizzle/0050_institution_contracts_and_settlement_accounting.sql --apply  # 실제 적용
   ```
2. 관리자 > 결제·정산 관리 > **기관 계약** 탭에서 계약을 등록하고(기간·예산), 활성화합니다.
3. 같은 탭의 **반 연결**에서 계약 반을 연결하고, **기관 소속 회원**에서 학생·교사를 지정합니다.
4. 교사는 교사 포털 > 첨삭 정산에서 활동 내역과 정산 제외를 확인합니다.

## 1단계에서 하지 않은 것 (2단계)

Codex 설계 중 규모가 커서 미룬 항목입니다. 필요가 확인되면 이어서 진행합니다.

- 예산 예약의 만료 복구(임대 토큰·만료 감시): 지금은 작업 실패 시 즉시 되돌리지만, 서버가 중간에 멈추면 차감이 남을 수 있음
- 반·소속의 기간 이력(`effectiveFrom/To`)과 계약 갱신 체인: 지금은 현재 연결만 저장하고 변경 이력은 감사 기록으로 확인
- 워크북 서술형 AI 평가의 예산 차감(학생 AI 평가·교사 AI 초안·과제 AI 첨삭은 연결됨)
- 여러 기관 계약에 속한 학생의 계약 선택 화면(지금은 막고 안내)
- 장부 기록 실패 시 자동 점검 도구(실패한 활동은 개별 정산 대상으로 집계되므로 확정 전 확인 필요)
- 실제 MySQL 동시성 통합 테스트(지금은 조건부 갱신 구조와 흐름을 단위 테스트로 검증)

## 결정이 필요한 항목 (현재 기본값)

| 결정 | 현재 기본값 |
|---|---|
| 예산이 소진되면 | 새 첨삭·AI·관리 이용을 막음(조회·수정은 가능) |
| 교사 첨삭 예산 소진 시 교사 업무 | 기관 담당자의 증액 전까지 새 첨삭 불가 — 운영 방식에 따라 "경고만"으로 바꿀 수 있음 |
| 기관 소속 학생의 개인 과외 | 그 학생에 대한 교사의 모든 첨삭이 개별 정산 제외 |
| 기관 소속 교사의 개인 학생 | 기관 소속으로 지정하면 교사의 모든 활동이 제외(전속 교사). 일부만 제외하려면 지정하지 않고 반 단위 연결을 사용 |
| 실패한 AI 시도 | 차감하지 않음(성공한 것만) — 단, 평가 엔진이 내부적으로 대체 결과를 돌려주는 경우는 아직 구분하지 못함 |

## 이용 방식: 횟수제·기간제와 소진 시 동작 (마이그레이션 0051)

계약마다 관리자가 이용 방식을 정한다(`institution_contracts.usageMode`, `overageAction`). 기본값은 기존 동작과 같은 "횟수제 + 소진 시 차단"이다.

| 이용 방식 | 소진 시 동작 | 새 이용 가능 조건 | 예산 숫자의 의미 |
|---|---|---|---|
| 횟수제 | 차단(기본) | 활성 + 계약 기간 안 + 예산 횟수 이내 | 한도 |
| 횟수제 | 경고 후 계속 | 활성 + 계약 기간 안 (한도를 넘어도 이용) | 기준선. 넘긴 횟수는 "초과 N"으로 표시 |
| 기간제 | (해당 없음) | 활성 + 계약 기간 안 | 참고용. 사용 횟수는 기록만 한다 |

- 어느 방식이든 계약이 중지·종료되었거나 기간 밖이면 새 이용은 막힌다.
- 차감(사용 기록)은 모든 방식에서 계속된다. 그래서 사용 내역과 정산 제외 근거는 같은 형태로 남고, 초과분은 관리자 계약 목록에서 확인한다.
- 이용 방식을 바꾸는 것은 관리자만 할 수 있고 사유가 감사 기록(`policy_changed`)에 남는다. 바꾼 뒤의 새 이용부터 적용되며 이미 쓴 횟수는 그대로다.
- 횟수제·차단인 계약만 "이미 쓴 횟수보다 작게 예산을 줄일 수 없다"는 제한을 받는다.
- 학생의 AI 평가 화면은 기간제이면 "계약 기간 동안 횟수 제한 없이 이용", 초과 상태이면 초과 횟수와 문의 안내를 보여 준다.
- 적용: `node scripts/apply-migration.mjs drizzle/0051_institution_contract_usage_policy.sql --apply` (0050 다음에 실행)
