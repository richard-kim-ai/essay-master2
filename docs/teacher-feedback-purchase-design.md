# 교사 첨삭지도권(횟수권) 설계·구현 기록

> 상태: **구현됨**(2026-10-14). 결제는 아직 임시(mock)이며 실제 PG 연동 전입니다.
> 기준: 『가격 및 환불정책』 1·2·4·6·7·8조.
> 건별 결제(핵심 3,900 / 일반 6,900 / 종합 9,900원)는 **폐지**하고 첨삭지도권으로 전환했습니다.

## 1. 상품

**일반 첨삭 1종**(논리·구성·근거에 대한 교사 첨삭)을 **횟수권 3종**으로 판매합니다.

| 상품 | 가격 | 1회당 | 6,900원×횟수 대비 |
|---|---|---|---|
| 교사 첨삭지도권 1회분 | 6,900원 | 6,900원 | 할인 없음 |
| 교사 첨삭지도권 3회분 | 19,900원 | 약 6,633원 | 약 4% 할인 |
| 교사 첨삭지도권 5회분 | 31,900원 | 6,380원 | 약 7.5% 할인 |

- 유효기간: **구매일부터 90일**(AI 추가권과 같은 방식).
- ⚠ **가격과 유효기간은 구현 시 제안한 값입니다.** 요청에는 "횟수가격 3종"만 있고 금액·기간이 정해져 있지 않았습니다. `shared/plans.ts`의 `TEACHER_FEEDBACK_PASSES`·`TEACHER_FEEDBACK_PASS_PERIOD_DAYS`에서 한 곳만 고치면 요금 페이지, 구매 화면, 서버 결제 금액이 함께 바뀝니다. 바꾼 뒤에는 정책 문서(`server/refundPolicy.ts` 기본 문구 또는 관리자 화면)의 가격표도 맞춰야 합니다(테스트가 두 값의 일치를 검사합니다).

## 2. 확정된 결정

| # | 결정 | 내용 |
|---|---|---|
| ① | 구매·신청 자격 | **현재 이용 중인 유료 이용권이 있는 학습자**만 첨삭지도권을 구매한다(30일 상품은 '유료 이용 시작'을 눌러 기간 안, 추가권은 90일 안). 시작 대기 중이면 구매 불가(시작 안내). 이미 산 권으로 신청하는 것은 권의 유효기간·잔여 횟수만 본다 |
| ② | 기관 계약 학생 | 개인 결제를 막지 않는다. 기관 학생도 첨삭지도권을 구매해 신청할 수 있고, 기존 계약 경로(무료 요청)도 쓸 수 있다 |
| ③ | 교사 지급 | **계약급여로 따로 집행**한다. 권 가격과 별건이므로 정산(교사 월 정산)과 연결하지 않고, 교사 화면에는 금액을 표시하지 않는다 |
| ④ | 기존 무료 첨삭 | 이전·유예 처리 없이 정리한다. 신청이 없는 글(기관 계약 학생·관리자 제외)은 교사가 첨삭을 등록할 수 없다 |
| ⑤ | 완료 예정일 | 신청한 날부터 **주말을 뺀 3영업일**(한국 시간 기준 그날 23:59:59) |
| ⑥ | 상품 구조 | 일반 첨삭 1종, 횟수권 3종. 핵심·종합 등급과 평가항목 선택은 폐지 |

## 3. 완료 예정일이란

**담당 교사가 첨삭 결과를 전달하기로 고객에게 약속한 날짜**입니다.

- 신청한 날부터 토·일을 뺀 3영업일째 날 밤 11시 59분까지입니다. 공휴일은 반영하지 않습니다.
- 정책 4조에 따라 **신청 전에 화면에 미리 보여 주고**, 신청 후에는 학생·교사·관리자 화면에 모두 표시합니다.
- 이 날짜가 지나도 전달되지 않으면(**지연**) 학생은 **취소하고 횟수를 돌려받거나 그대로 기다릴 수 있습니다**(정책 8조). 교사 대기열과 관리자 목록에는 "기한 경과"로 표시합니다.
- 학생이 보완을 요청하면 그때부터 다시 3영업일로 계산합니다.
- 교사 지급과는 무관한 **고객과의 약속**입니다.

## 4. 사용자 흐름

```
[학생] 이용권(학습형 등) 이용 중 → 교사 첨삭지도권 구매(1·3·5회분, 앱 안 결제)
[학생] 글쓰기 화면의 '담당 교사 첨삭 요청' → 신청 대화상자
   안내: 남은 횟수, 담당 교사, 완료 예정일, 취소 시 횟수 복원
   '첨삭지도권 1회 사용해 신청' → 먼저 만료되는 권에서 1회 차감, 글이 담당 교사에게 제출됨
[시스템] 담당 교사에게 알림
[교사] 마이페이지 '첨삭 신청 대기열' → '첨삭하기' → 기존 첨삭 작성 화면에서 등록
[시스템] 첨삭 등록(또는 AI 초안 승인) 시 신청이 '전달 완료'가 되고 학생에게 알림
[학생] 전달 전: 언제든 취소 → 횟수 1회 복원 / 전달 후: 무료 보완 요청(횟수 추가 차감 없음)
```

권이 없으면 신청 대화상자에서 바로 구매할 수 있습니다(이용권 결제자만).

신청 가능 조건(서버가 신청 직전에 다시 검사): 학습자 계정, 사용할 수 있는 권(환불되지 않음·유효기간 안·남은 횟수 있음), 본인의 글(초안 또는 제출됨, 본문 있음), 같은 글에 진행 중인 신청 없음, 이미 끝난 첨삭 없음, 승인된 사람 교사(AI 봇 제외)가 담당으로 배정됨.

## 5. 데이터 모델 (마이그레이션 0056)

`teacher_feedback_passes` (권):

| 컬럼 | 설명 |
|---|---|
| `userId`, `productKey` | 구매자, `tf_pass_1` / `tf_pass_3` / `tf_pass_5` |
| `sessions`, `sessionsUsed` | 총 횟수, 사용한 횟수(결제 시점의 상품 정의를 보존) |
| `priceKrw`, `orderId` | 결제 금액, `payment_orders.id`(`planKey`에 `tf_pass_*` 기록) |
| `status` | `active` / `refunded` |
| `expiresAt` | 구매일부터 90일 |

`teacher_feedback_requests` (신청, 1건 = 권 1회 사용):

| 컬럼 | 설명 |
|---|---|
| `userId`, `essayId`, `passId`, `teacherId` | 학생, 글, 차감한 권, 신청 시점의 담당 교사 |
| `status` | `paid`(신청 완료·교사 대기) → `in_progress` → `delivered` / `cancelled` / `refunded` |
| `dueAt`, `deliveredAt`, `teacherFeedbackId` | 완료 예정일, 전달 시각, 결과 |
| `reworkCount`, `reworkNote`, `cancelledAt`, `cancelReason` | 보완·취소 정보 |

- 권 구매 확정(주문 `paid` + 권 생성)은 **한 트랜잭션**이다.
- 신청(차감 + 신청 생성 + 초안 글 제출 처리)도 **한 트랜잭션**이다. 차감은 `환불되지 않음 · 유효기간 안 · 사용 횟수 < 총 횟수`일 때만 되는 조건부 갱신이라 동시에 신청해도 횟수를 넘지 못한다.
- 취소(신청 취소 + 횟수 복원)도 **한 트랜잭션**이다. 돈을 환불하지 않으므로 '전달 전(열린 상태)에만 취소'하는 조건 하나로 교사의 동시 전달을 막는다.
- 이용권 결제 API(`billing.startCheckout`)는 `tf_pass_*`를 받지 않는다(테스트로 보장).

## 6. 서버(API) — `teacherFeedbackRequest.*`

| 프로시저 | 권한 | 내용 |
|---|---|---|
| `products` | 로그인 | 판매 중인 권 3종 |
| `passes` | 학습자 | 내 권(잔여·유효기간), 구매 가능 여부와 이유 |
| `purchasePass` | 학습자(이용권 결제자) | 권 구매 → 결제 → 권 생성. 결제 후 저장 실패 시 결제를 되돌린다 |
| `quote` | 학습자 | 신청 전 안내: 남은 횟수·완료 예정일·담당 교사·신청 가능 여부와 이유·구매 가능 여부·기관 계약 학생 여부 |
| `create` | 학습자 | 먼저 만료되는 권에서 1회 차감해 신청 + 교사 알림 |
| `mine` | 학습자 | 내 신청 목록(지연 여부 포함) |
| `cancel` | 본인 | 전달 전 취소 → 횟수 복원 |
| `requestRework` | 본인 | 전달된 첨삭의 무료 보완 요청(예정일 재계산) |
| `queue` / `start` | 승인된 담당 교사 | 대기열, 작업 시작 |
| `adminList` / `adminPasses` | 관리자 | 전체 신청·지연 건, 판매된 권(잔여·미사용 환불 예상액) |

전달 지점(`server/routers.ts`의 `teacherFeedback.create`·`update`, `teacherAi.approveDraft`)은 건별 때와 같다.
- 신청이 있는 글만 첨삭 등록 가능(관리자, 기관 계약 학생은 예외). 신청이 있으면 기관 예산을 차감하지 않는다.
- 등록·수정 시 열린 신청을 `delivered`로 바꾸고 학생에게 알린다.
- `essaySubmission.requestTeacher`(무료 요청)는 기관 계약 학생만 쓸 수 있다.

## 7. 환불 규칙(정책 7·8조 반영)

- **전달 전 취소**: 권 1회가 그대로 돌아온다(교사 배정·작업 착수·교사비 지급을 이유로 차감하지 않는다).
- **미사용 권의 환불**: 정책의 AI 횟수권과 같은 식 — 환불액 = 결제금액 × 미사용 횟수 ÷ 총 횟수, 원 미만은 이용자에게 유리하게 올림하되 결제금액을 넘지 않는다(`unusedPassRefundKrw`). 관리자 화면의 권 목록에 **미사용 환불 예상액**을 표시한다.
- **관리자 환불**: `/admin/billing`의 결제 내역에서 주문을 환불하면 권이 `refunded`가 되어 더 이상 신청에 쓰이지 않고, 그 권으로 진행 중이던 신청은 `refunded`로 닫힌다(이미 전달된 신청은 그대로).
- 법정 청약철회·하자·미성년자 취소 등은 관리자가 결제 내역에서 처리한다.

## 8. 화면

- **요금 페이지**: 권 3종 + "이용권 결제자만 구매·신청할 수 있습니다." (`TEACHER_FEEDBACK_PURCHASE_OPEN`으로 '준비 중' 표시 제어)
- **결제 화면(`/checkout`)**: 이용권 아래 '교사 첨삭지도권' 구매 영역(남은 횟수·가장 먼저 만료되는 권)
- **학생**: 글쓰기 화면의 '담당 교사 첨삭 요청' → 신청 대화상자, 화면 아래 '내 교사 첨삭 신청'(상태·완료 예정일·취소·지연 시 선택·보완 요청)
- **교사**: 마이페이지 '첨삭 신청 대기열' 탭(금액 비표시)
- **관리자**: `/admin/billing`의 '교사 첨삭 신청' 탭(신청 목록 + 판매된 권 목록)

## 9. 남은 과제·주의

- **결제는 임시(mock)** 이다. 실제 금액을 받기 전에 PG 연동과 실제 환불 처리가 필요하다.
- **미사용 권의 부분 환불**은 예상액을 표시하는 데까지만 구현했다. 관리자 환불은 주문 전체 환불이며, 일부를 쓴 권의 부분 환불 금액 지급은 수동 처리가 필요하다(AI 추가권과 같은 한계).
- 유효기간이 지난 권은 새 신청에 쓸 수 없지만, 정책에 따라 미사용 잔액의 환급 신청은 가능하다(수동 처리).
- 공휴일은 영업일 계산에 반영하지 않는다.
- 데이터베이스 마이그레이션 `0055`, `0056`을 코드 배포 전에 순서대로 적용해야 한다.
- 실제 DB에서의 트랜잭션(차감·취소·구매 확정) 동작은 자동 테스트로 검증하지 못했다(DB 계층은 모의 객체로 검증).
