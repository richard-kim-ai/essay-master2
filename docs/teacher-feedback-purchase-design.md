# 교사 첨삭지도 건별 결제 (앱 안 추가 결제)

> 상태: **구현됨**(2026-10-13). 결제는 아직 임시(mock)이며 실제 PG 연동 전입니다.
> 기준: 『가격 및 환불정책』 1·2·4·6·7·8·11조.

## 1. 확정된 결정

| # | 결정 | 내용 |
|---|---|---|
| ① | 신청 자격 | **현재 이용 중인 유료 이용권이 있는 학습자**(30일 상품은 '유료 이용 시작'을 눌러 기간 안, 추가권은 90일 안). 결제만 하고 시작 전이면 신청 불가(시작 안내). 무료 체험만 쓰는 사용자는 신청할 수 없다 |
| ② | 기관 계약 학생 | **개인 결제를 막지 않는다.** 기관 계약 학생도 상품을 추가 결제해 별도로 신청할 수 있고, 기존 계약 경로(무료 요청)도 그대로 쓸 수 있다 |
| ③ | 교사 지급 | **계약급여로 따로 집행**한다. 상품 가격과 별건이므로 신청·결제 금액을 정산(교사 월 정산)과 연결하지 않고, 교사 화면에는 금액을 표시하지 않는다. 기존 첨삭 활동 장부 기록은 그대로 둔다 |
| ④ | 기존 무료 첨삭 | **이전·유예 처리 없이 정리**한다. 신청·결제가 없는 글(기관 계약 학생 제외)은 교사가 첨삭을 등록할 수 없다 |
| ⑤ | 완료 예정일 | 결제한 날부터 **주말을 뺀 3영업일** 안(한국 시간 기준 그날 23:59:59). 공휴일은 반영하지 않는다 |

## 2. 완료 예정일이란

> **담당 교사가 첨삭 결과를 전달하기로 약속한 날짜**입니다.

- 신청(결제)한 날부터 토·일을 뺀 3영업일째 날의 밤 11시 59분까지입니다. 예) 수요일 오전에 결제 → 다음 주 월요일까지.
- 정책 4조에 따라 **결제하기 전에 화면에 미리 보여 주고**, 신청 후에는 학생·교사·관리자 화면에 모두 표시됩니다.
- 이 날짜가 지났는데 아직 전달되지 않았다면(**지연**), 학생은 정책 8조에 따라 **전액 환불을 받거나 그대로 기다리기**를 선택할 수 있습니다. 교사 대기열과 관리자 목록에는 "기한 경과"로 표시됩니다.
- 학생이 결과에 대한 보완을 요청하면 완료 예정일이 그때부터 다시 3영업일로 계산됩니다.
- 이 날짜는 교사 지급이나 정산 금액과는 무관한 **고객과의 약속**입니다.

## 3. 사용자 흐름

```
[학생] 글쓰기 화면에서 '담당 교사 첨삭 요청' → 신청 대화상자
   ① 상품 선택(핵심/일반/종합) · 핵심은 평가항목 1~2개 선택
   ② 안내 확인: 가격, 완료 예정일, 담당 교사, 환불 기준(전달 전 취소 시 전액)
   ③ 앱 안에서 결제(임시 결제) → 글이 담당 교사에게 제출됨(상태: paid)
[시스템] 담당 교사에게 알림
[교사] 마이페이지 '첨삭 신청 대기열' → '첨삭하기'(작업 중) → 기존 첨삭 작성 화면에서 등록
[시스템] 첨삭 등록(또는 AI 초안 승인) 시 신청이 '전달 완료'가 되고 학생에게 알림
[학생] 전달 전: 언제든 취소 → 전액 환불 / 전달 후: 보완 요청(무료)
```

신청 가능 조건(서버가 결제 직전에 다시 검사): 학습자 계정, 이용 중인 유료 이용권, 본인의 글(초안 또는 제출됨, 본문 있음), 같은 글에 진행 중인 신청 없음, 이미 끝난 첨삭 없음, 승인된 사람 교사(AI 봇 제외)가 담당으로 배정됨.

## 4. 데이터 모델

테이블 `teacher_feedback_requests`(마이그레이션 0056):

| 컬럼 | 설명 |
|---|---|
| `userId`, `essayId` | 신청 학생, 대상 글 |
| `productKey` | `tf_core` / `tf_standard` / `tf_comprehensive` (`shared/plans.ts`) |
| `priceKrw` | 결제 시점 가격(가격이 바뀌어도 보존) |
| `scopeJson` | 핵심 첨삭의 선택 평가항목(논리·구성·근거·표현 중 1~2개) |
| `teacherId` | 신청 시점의 담당 교사 |
| `status` | `paid` → `in_progress` → `delivered` / `cancelled` → `refunded` |
| `orderId` | `payment_orders.id` (`planKey`에 `tf_*`를 기록) |
| `dueAt`, `deliveredAt`, `teacherFeedbackId` | 완료 예정일, 전달 시각, 결과 |
| `reworkCount`, `reworkNote` | 보완 요청 횟수·내용 |
| `cancelledAt`, `cancelReason` | 취소 정보 |

- 결제 확정(주문 `paid` + 신청 생성 + 초안 글 제출 처리)은 **한 트랜잭션**이다.
- 이용권 결제 API(`billing.startCheckout`)는 `tf_*` 상품을 받지 않는다(테스트로 보장).

## 5. 서버(API)

| 프로시저 | 권한 | 내용 |
|---|---|---|
| `teacherFeedbackRequest.quote` | 학습자 | 결제 전 안내: 가격·완료 예정일·담당 교사·신청 가능 여부와 이유·기관 계약 학생 여부 |
| `.create` | 학습자 | 조건 검사 → 주문 → 결제 → 신청 생성 + 교사 알림. 결제 후 저장 실패 시 결제를 되돌린다 |
| `.mine` | 학습자 | 내 신청 목록(지연 여부 포함) |
| `.cancel` | 본인 | 전달 전 취소 → **전액 환불**(취소를 먼저 선점 → 환불 → 실패 시 복구, 환불 중 교사 전달과의 경쟁 방지) |
| `.requestRework` | 본인 | 전달된 첨삭의 무료 보완 요청(예정일 재계산) |
| `.queue` / `.start` | 승인된 담당 교사 | 대기열 조회, 작업 시작 |
| `.adminList` | 관리자 | 전체 신청·지연 건 조회 |

전달 지점(교사가 결과를 등록하는 곳)은 `server/routers.ts`의 `teacherFeedback.create`·`update`, `teacherAi.approveDraft`이다.
- `create`/`approveDraft`: 신청이 있는 글만 첨삭 가능(관리자, 기관 계약 학생은 예외). 신청이 있으면 기관 예산을 차감하지 않는다(학생이 이미 결제).
- 등록·수정 시 열린 신청을 `delivered`로 바꾸고 학생에게 알린다.
- `essaySubmission.requestTeacher`(무료 요청)는 **기관 계약 학생만** 쓸 수 있다.
- 관리자가 교사 첨삭 주문을 환불하면 신청도 `refunded`가 된다(`markOrderRefunded`).

## 6. 화면

- **요금 페이지**: 가격권 3종 + "이용권 결제자만 신청할 수 있습니다." (`TEACHER_FEEDBACK_PURCHASE_OPEN`으로 '준비 중' 표시 제어)
- **학생**: 글쓰기 화면의 '담당 교사 첨삭 요청' → 신청 대화상자(`TeacherFeedbackRequestDialog`), 화면 아래 '내 교사 첨삭 신청'(`MyTeacherFeedbackRequests`: 상태·완료 예정일·취소·지연 시 선택·보완 요청)
- **교사**: 마이페이지 '첨삭 신청 대기열' 탭(`TeacherFeedbackQueue`, 금액 비표시)
- **관리자**: `/admin/billing`의 '교사 첨삭 신청' 탭(`AdminTeacherFeedbackRequests`)

## 7. 남은 과제·주의

- **결제는 임시(mock)** 이다. 실제 금액을 받기 전에 PG 연동과 실제 환불 처리가 필요하다.
- 공휴일은 영업일 계산에 반영하지 않는다.
- 지연 시 '무료 보완' 선택은 별도 버튼 없이 **그대로 기다리기**로 처리한다(교사가 계속 작업). 전달 후 범위 미달은 '보완 요청'으로 처리한다. 법정 사유 환불은 관리자가 결제 내역에서 처리한다.
- 데이터베이스 마이그레이션 `0056_teacher_feedback_requests.sql`을 코드 배포 전에 적용해야 한다(`node scripts/apply-migration.mjs ... --apply`).
- 실제 DB에서의 트랜잭션·취소 선점 동작은 자동 테스트로 검증하지 못했다(DB 계층은 모의 객체로 검증).
