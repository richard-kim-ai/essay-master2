# AI 학습 데이터 수집·가명처리·폐기 운영 정책안

> **법률 검토 전 운영 초안** — 본 문서는 기능 설계와 내부 운영 절차를 위한 초안입니다. 실제 서비스 시행 전에 개인정보보호 및 교육 서비스 전문 법률 검토를 거쳐 사업자 정보, 보유 기간, 위탁·국외 이전, 보호자 동의 기준과 처리 기한을 확정해야 합니다.

## 1. 적용 범위와 원칙

본 정책은 학생 답안, 교사 첨삭, AI 초안 및 교사 수정 이력을 대상으로 한다. 서비스 제공용 원본 데이터와 AI 품질 개선 후보 데이터는 목적·접근 권한·보관 수명주기를 분리한다. AI 품질 개선은 기본 서비스에 필요한 처리가 아니므로, 별도 선택 동의와 교사 승인 사례에 한정한다.

| 데이터 구분 | 목적 | 접근 권한 | AI 개선 활용 |
|---|---|---|---|
| 원본 학습 답안 | 학습·교사 지도·기록 제공 | 학생, 배정 교사, 권한 있는 관리자 | 자동 활용 금지 |
| 교사 최종 첨삭 | 지도 결과 제공·품질 검토 | 작성 교사, 학생, 권한 있는 관리자 | 별도 동의·교사 승인 후 후보화 |
| AI 초안·수정 비교 | 교사 보조·품질 점검 | 작성 교사, 권한 있는 관리자 | 교사 건별 승인 후 후보화 |
| 가명 처리 사례 | 스타일 참조·품질 평가 | 승인된 교사, 관리자 | 승인 상태와 보관 기간 내에서만 사용 |

## 2. 수집과 승인 절차

회원가입 시 이용약관과 개인정보처리방침은 전문 확인 뒤 필수 동의로 수집한다. 학생·학부모의 AI 품질 개선 데이터 활용은 선택 동의로 구분하며, 미동의 상태에서도 학습·교사 첨삭 핵심 기능을 이용할 수 있어야 한다. 첨삭교사는 AI 보조 봇 운영·승인 규정에 필수 동의하고, 자신의 첨삭 사례를 스타일 참조로 등록할 때마다 학습 후보 활용 여부를 확인한다.

가명 처리 후보는 다음 순서로 생성한다.

1. 교사가 최종 첨삭을 확정한 뒤 후보를 등록한다.
2. 시스템이 이메일, 전화번호, 식별번호, 날짜 형식 등 직접 식별 가능 패턴을 우선 대체한다.
3. 교사가 남은 성명·학교·지역·희귀 사건 등 재식별 가능 내용을 점검하고 수정한다.
4. 교사 승인 뒤 관리자가 AI 스타일 참조 또는 품질 평가 사용 여부를 검수한다.
5. 승인된 사례만 교사별 AI 컨텍스트에 포함하며, 모델 재학습 데이터로 바로 전송하지 않는다.

> 가명처리는 재식별 위험을 자동으로 완전히 제거하지 않는다. 자동 대체 후에도 사람 검수와 목적·권한 통제가 필요하다.[1]

## 3. 보관·철회·폐기 흐름

| 이벤트 | 즉시 조치 | 후속 처리 | 감사 기록 |
|---|---|---|---|
| 선택 동의 철회 | 신규 개선 후보 수집 중단 | 승인 대기·미사용 후보를 `withdrawn`으로 전환 | 요청자·시각·처리자·결과 |
| 사례 승인 철회 | AI 스타일 컨텍스트에서 즉시 제외 | 다음 배치에서 파기 대상 표시 | 사례 ID·철회 사유·처리 시각 |
| 삭제 요청 | 요청 접수·본인 확인 | 법률·계약상 보존 필요 여부 검토 후 삭제 또는 제한 처리 | 요청 ID·처리 근거·완료 시각 |
| 보관 기간 만료 | 해당 데이터 사용 중단 | 검수된 파기 작업으로 삭제 또는 정책상 허용된 비식별 통계만 보존 | 대상 수·실행자·오류 목록 |

보관 기간은 서비스 계약, 법률 검토, 교육기관 정책을 반영해 관리자 설정으로 확정해야 하며, 현재 초안은 고정 일수를 자동 적용하지 않는다. 자동 폐기 작업을 도입할 때에는 대상 미리보기, 관리자 승인, 실행 로그, 복구 불가 경고, 실패 재시도와 독립적인 백업·복구 정책을 함께 구현한다.

## 4. 품질 관리와 모델 개선의 경계

교사별 AI 보조 봇은 모델 자체를 지속 재학습하는 기능이 아니라, 승인된 스타일 지침·가명 사례·루브릭을 참조하여 **교사 검토용 초안**을 만드는 기능으로 시작한다. AI 초안과 교사 최종 수정본의 차이는 품질 평가 후보로만 보관하며, 독립 평가 세트에서 정확성·유해성·교사 선호도를 검증하기 전에는 모델 미세조정에 사용하지 않는다. 고품질·일관성·평가 분리가 모델 개선의 전제라는 원칙을 따른다.[2] [3]

## 5. 책임과 점검

관리자는 정책 버전, 동의 이력, 철회 상태, 승인 사례 상태, 데이터 요청 처리 이력을 정기 점검한다. 교사는 본인의 AI 스타일 프로필과 사례를 검토·철회할 수 있어야 하며, 학생과 학부모는 열람·정정·AI 개선 활용 철회·삭제 요청을 제출할 수 있어야 한다. AI 결과는 교사 승인과 전문적 판단을 대체하지 않는다는 안내를 학생 화면에 유지한다.
