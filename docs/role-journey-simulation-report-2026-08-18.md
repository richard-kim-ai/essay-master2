# 역할별 1단계 여정 시뮬레이션 결과

**점검일:** 2026-08-18  
**범위:** 초등·중고등·고등/대입·일반/직장인 학생의 1단계 학습, 첨삭교사 승인형 AI 초안, 관리자 문제은행·수료증 운영  
**검증 원칙:** 실제 사용자 학습기록, 이메일 발송, 유료 AI 호출, 수료증 발급·취소 및 문제은행 데이터 변경은 운영 데이터를 보호하기 위해 수행하지 않았습니다. 대신 화면 렌더링, 권한 경로, 입력 계약, 기존 데이터·자동화 검증을 조합해 점검했습니다.

## 1. 학생 여정

| 점검 항목 | 결과 | 근거 |
|---|---|---|
| 학생 가입 시 과정 선택 | 통과 | 학생 가입 화면에서 초등·중고등·고등/대입·일반/직장인 선택지를 제공하며 서버도 학생 과정 누락 요청을 거부합니다. |
| 선택 과정 전용 커리큘럼 | 통과 | 공통 과정 매핑으로 선택값을 사용자 태그에 저장하고, 로그인 후 과정 키로 복원합니다. 기존 `일반` 태그도 일반/직장인 과정으로 호환 처리했습니다. |
| 4개 과정 1단계 워크북 | 통과 | `elementary`, `middle_high`, `high_univ`, `general_adult` 워크북 1단계 화면이 모두 렌더링되며 과정별 제목과 고정 기출문제 영역을 확인했습니다. |
| 서술형 AI 평가 | 통과 | 기존 검증에서 주제 적합성·주장·근거·비교/분석·표현/구성 5개 기준, 답안 인용 확인, 무의미·오프토픽 분기까지 자동화 검증되었습니다. |
| 수료증 신청·미리보기 | 통과 | 수료증 화면에서 과정별 레벨 수료증과 미리보기/발급 진입점을 확인했습니다. |

> **발견 및 수정:** 기존 가입 화면에는 학생/학부모 구분만 있고 과정 선택이 없어, 신규 학생의 맞춤 커리큘럼 기준이 명확하지 않았습니다. 학생 전용 과정 선택, 서버 유효성 검사, 공통 매핑과 레거시 `일반` 태그 호환을 추가했습니다.

## 2. 첨삭교사 여정

| 점검 항목 | 결과 | 근거 |
|---|---|---|
| 승인형 AI 초안 화면 | 통과 | 제출물 상세 경로에서 `AI 첨삭 초안 생성` 진입과 교사 최종 코멘트 입력 영역을 확인했습니다. |
| 권한·배정 검증 | 통과 | 서버는 승인된 교사 또는 관리자만 접근시키고, 교사는 자신에게 배정된 학생의 제출물만 처리하도록 제한합니다. |
| 수정 이력·최종 발송 | 통과 | AI 초안 수정 이력 저장과 승인 후 학생 공개·알림 발송 절차가 라우터 계약에 연결돼 있습니다. |
| 교사 스타일 보조 봇 운영 | 통과 | 관리자 AI 운영 화면에서 교사별 프로필, 승인 사례 및 동의 감사 흐름의 화면 진입을 확인했습니다. |

## 5. 제한사항 및 운영 권고

1. 실제 신규 회원의 이메일 인증, 실시간 AI 생성, 수료증 신규 발급·취소, CSV 업로드·삭제는 운영 DB와 외부 발송·AI 비용에 영향을 주므로 본 시뮬레이션에서는 실행하지 않았습니다. 운영 전용 테스트 계정과 격리된 스테이징 DB를 마련한 뒤 완전한 쓰기 경로 E2E 테스트를 권고합니다.
2. 학부모 계정은 학생의 연결 상태에 따라 과정이 결정되므로, 향후 가입 또는 연결 승인 화면에서 ‘연결된 학생의 과정’을 분명히 표시하는 안내를 추가하는 것이 좋습니다.
3. 수료증 발급 조건(진도·평가·승급 승인)이 실제 운영 정책과 일치하는지 관리자와 교사가 공동으로 점검한 후 발급 자동화 범위를 확정해야 합니다.
4. 기존 8개 스킵 테스트는 운영 DB 변경 또는 외부 AI 호출을 수반할 수 있습니다. 별도 테스트 테넌트가 준비되면 이를 E2E 시나리오로 전환해야 합니다.
